# 离散特征的处理——Embedding

> 假设有用户的 IP 地址, 其取值为 $34$ 个省份自治区, 如何将其数值化?

容易想到, 直接将类别映射成序号, 例如:
```
北京 --> 1
上海 --> 2
浙江 --> 3
   ...
```
但这样不同地址就有数值的大小之分, 事实上这些不同的地址都是平等的, 因此要设法规避.

## One-hot 编码
将不同类别映射成一个向量, 例如上述例子中 $34$ 个省份自治区就映射成 $34$ 维向量：
$$
\text{北京} \to \begin{pmatrix}1 \\\\ 0 \\\\ \vdots \\\\ 0\end{pmatrix},\qquad 
\text{上海} \to \begin{pmatrix}0 \\\\ 1 \\\\ \vdots \\\\ 0\end{pmatrix}. 
$$
但这样如果遇到类别数量很庞大的情况, 例如某 APP 的用户可能会有上亿个, 这样向量的维度也会很庞大, 运算成本会很大. 因此此方法也仅在类别数量比较小的时候适用.

## Embedding
> 解决 One-hot 编码向量维数过大的问题

**目标: 将每一类映射成一个低维向量, 例如这里我们映射成 $5$ 维向量**

我们需要通过机器学习得到每个类别的 $5$ 维向量中的参数值.

不同地区的用户喜欢的内容可能有差别, 例如
```
北京 = ['豆汁', 炸酱面', ...]
上海 = ['葱油拌面', '红烧肉', ...]
...
```
于是模型学得的参数值也有所差别.

> 如何学习 Embedding 之后向量的参数?

- 随机初始化向量, 例如 
  ```
    北京 -> [ 0.12, -0.07, 0.03, 0.19, 0.02]
    上海 -> [-0.21,  0.18, 0.05, 0.08, 0.25]
    广东 -> [ 0.09,  0.11,-0.14,-0.09, 0.11]
    ...
  ```
- 将这些向量传入后续排序模型预估用户对某物品的兴趣分数 $\hat y$
- 与真实值进行比较, 计算 Loss: $\mathcal L=BCE(\hat y, y)=-[y\log\hat y+(1-y)\log(1-\hat y)]$.
- 通过反向传播更新参数.

通过 Embedding 层, 最后得到 $5\times 34$ 维矩阵.
